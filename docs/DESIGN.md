# 2D Weekend Mall 设计

## 产品含义

`2D` 代表“两天周末”：用户在周末可以不用加班，轻松完成一次可预期、低负担的购物。界面采用低饱和浅青、暖米黄与少量活力橙，突出“周末休息感”。

## 业务闭环

1. 商品搜索：关键字匹配商品名、标签、品牌和描述。
2. 购物车：同一用户在同一浏览器会话中维护数量。
3. 下单：校验购物车和地址，生成订单与订单项。
4. 支付：模拟微信、支付宝、银行卡，支付后生成物流单。
5. 查询订单：支持全量列表和单号详情。
6. 物流：支付订单提供节点、当前位置、预计送达和签收码。

## 技术架构

商城采用单体 Spring Boot 应用，数据层用内存仓储模拟真实购物流程，避免示例环境依赖数据库。前端使用原生 HTML/CSS/JS，后端提供同源 REST API。

客服插件不把业务规则复制进 Harness，而是作为 Harness 的适配层，通过 Java `HttpClient` 调用商城 REST API。这样商城仍是业务边界，插件只暴露模型可理解的能力。

客服 UI 使用右下角浮动对话层，展示为“真人客服 + 信息卡片”的形态：工具调用只显示状态提示，不展示模型思考；商品、订单和物流结果会在气泡内渲染成轻量卡片，让用户直接看到商城中的关键数据。

## Harness 插件

插件 ID 是 `mall-weekend-assistant`。注册能力：

- `search_products`：搜索虚拟商品。
- `get_product`：查询单个商品详情。
- `query_orders`：查询用户订单列表。
- `get_order`：查询单个订单详情。
- `query_logistics`：查询支付后的物流轨迹。

插件通过 `registerSystemPrompt` 注入客服约束：只答商城相关内容、不虚构数据、必要时用固定演示用户 `customer-1`、不承诺真实退款和支付到账。`POST_TOOL_USE` 会发布 `mall-weekend-assistant.tool.used` 事件，体现插件事件总线能力。

插件默认读取商城地址 `mall.base-url`，默认值 `http://127.0.0.1:18080`。
